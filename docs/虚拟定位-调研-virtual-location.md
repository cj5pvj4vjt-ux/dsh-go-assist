## 2. 「模拟位置信息应用」权限：已经是选中状态，不需要再开

现象：**全程没有任何权限提示**（没有出现「未选择模拟位置应用」之类）。

依据（对照 FakeTraveler 源码，见 `/root/workspace/projects/虚拟定位-FakeTraveler/fakesrc/`）：

- `MockedLocationService.startMockedService()` 先给 **GPS / NETWORK / FUSED** 三个 provider 各建一个 `MockedLocationProvider`，全部建成功后才 `postValue(MockState.MOCKED)`；
- Android 12+ 里 `LocationManager.addTestProvider()` 只有**被设为「模拟位置信息应用」的 App** 才能调用，否则抛 `SecurityException` → 走到 `MOCK_ERROR`（提示「未应用…」），而 `MockedLocationProvider.startup()` 内部还会重试 3 次；
- 我们看到的正是 `MOCKED` 分支的表现（「应用了模拟的位置。」+ 按钮变「停止」）。

→ 所以 **开发者选项 → 选择模拟位置信息应用 → 虚拟旅者** 这台机器上本来就选好了，任务里的第 2 步不需要用户再点。

## 3. 验证：**未能证实生效**（关键，别当成成功）

| 尝试 | 屏幕 | 看到什么 | 判断 |
|---|---|---|---|
| 高德地图（后台屏） | `b14`/`b15` | 定位在 **沈阳 · 浑南 · 朗月街浑南中路**（124 路「2分钟:2站」实时数据，底部「回家·12分钟」），不是上海 | 仍是真实位置 |
| Google 地图（后台屏） | `b17`/`b22` | 蓝点在 **沈阳 · 浑南 · 朗月街 / 真爱西餐厅** 一带；点「路线」时起点是空的「选择出发地」（说明它当时没拿到当前位置） | 没看到上海 |
| vivo **天气** | `b13` | 页面直接提示 **「请开启定位服务」**，城市是「浑南区」 | 指向系统定位没开/拿不到位置 |
| vivo **指南针** | `b12` | 「纬度 `--` · 经度 `--` · 海拔 `--`」（罗盘能转，说明传感器正常，只是没位置） | 同上 |

结论与可能原因（按可能性排）：

1. **系统「位置信息」总开关可能是关的**：天气提示「请开启定位服务」、指南针三项位置全是 `--`，都指向「系统根本没给任何 App 位置」。这种状态下，任何虚拟定位都不会被别的 App 看到——这也是最需要用户动手的一条。
2. 即使定位开着，**高德/微信/钉钉这类 App 常用自家网络定位或有反作弊**，不认 Android 的模拟位置；高德显示的真实位置也可能是它自己的基站/Wi-Fi 定位结果。
3. 这些 App 都跑在 DSH 的后台虚拟屏上，**Google 地图在那块屏上并没有拿到实时定位**（路线页起点为空），它显示的蓝点可能是缓存的旧位置——所以后台屏的截图只能算弱证据。

**因此：不能写「虚拟定位生效」。** 目前只能确定「FakeTraveler 已经把假位置推给系统了」，不能确定「别的 App 真的读到了假位置」。

## 4. 用户 30 秒就能做完的验证（下次复验按这个来）

1. 解锁手机 → 下拉快捷开关，确认 **「定位 / 位置信息」是打开的**（这是最可能的卡点）。
2. 打开 **虚拟旅者** → 纬度 `31.2304`、经度 `121.4737` → 点 **「应用」**，等到提示「应用了模拟的位置。」、按钮变「停止」。
3. 任选一种看结果（**优先用指南针，最直接**）：
   - **指南针（vivo 自带）**：纬度应显示 **31.2304** 左右、经度 **121.4737** 左右 —— 数字对上了就是真的生效；
   - **Google 地图 / 高德**：蓝点应落在上海人民广场（上海市黄浦区，南京东路/西藏中路附近）；
   - **天气 App**：城市应变成「上海」。
4. 如果蓝点还是真实位置：先换 **Google 地图 + 指南针** 再看（这两类最认 Android 模拟位置）；还是不对，就是该 App 不认模拟位置，不是设置没做对。

## 5. 怎么停止 / 恢复真实定位

- **最直接**：回到「虚拟旅者」主界面，点 **「停止」**（就是刚才「应用」那个按钮）→ 底部提示 **「模拟已停止」** → 立即恢复真实定位（本次实测过：`b19`）。
- **App 不在眼前**：从最近任务里划掉「虚拟旅者」，或 设置 → 应用 → 虚拟旅者 → **强行停止**。FakeTraveler 的模拟挂在它自己的 Service 上，Service 一结束就不再推假位置。
- **不用改开发者选项**：「选择模拟位置信息应用」保持选中不会持续生效，只有 App 里按了「应用」才会推假位置，按「停止」/结束进程就停。
- 想要「以后都不模拟」：同上强制停止即可，系统设置不用动。

## 6. 重启后是否保留

- **模拟本身不保留**：FakeTraveler 重启后按钮回到「应用」（`MainActivity.onCreate` 里 `endTime` 已过期就重置），需要重新点一次；模拟用的 test provider 也随进程退出而消失，重启手机后不会自动继续。
- **「选择模拟位置信息应用」这个系统设置会保留**（不随重启丢），所以下次只需要打开 App 点「应用」这一步。
